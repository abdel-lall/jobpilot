# UI improvements

Phases 1–18 are the completed functional roadmap. Their specifications, validation records, and notes stay as they are. Do not revise those phase documents to describe visual redesign work.

UI improvements are documented separately in this directory. Each improvement gets its own numbered spec as the redesign proceeds, for example `01-auth-pages.md`. A spec here describes the UI contract for that slice: what changes visually, what existing behavior must stay, and how to validate it.

These specs may evolve as the UI work progresses. Update the relevant UI-improvement spec when the design contract changes. Leave `specs/requirements.md`, `specs/tech-stack.md`, `specs/roadmap.md`, `specs/status.md`, and the phase directories unchanged unless a human explicitly asks to edit them.

Implementing a UI improvement is separate from the phase workflow. Do not start implementation from a UI spec until that spec has been reviewed and a human has approved the work.
